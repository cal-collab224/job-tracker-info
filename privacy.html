Privacy policy

Last updated: 20 October 2026

Job Tracker 2027 is a personal vacancy tracker operated by its owner. This policy describes the application and its public information pages. The tracker is intended for the owner's use, rather than public account registration.

Information the tracker uses

The connected Microsoft OneDrive workbook contains vacancy records, source lists, search preferences, review decisions, application statuses and notes. The tracker reads that workbook and updates vacancy facts and run information while preserving the owner's application information.

Configured search services receive vacancy-search queries. Employer websites, recruitment platforms and feeds receive requests for public vacancy information. Search results and advertised facts are processed to verify, classify and deduplicate opportunities.

Google and Gmail access

Google authorisation requests only https://www.googleapis.com/auth/gmail.send. This permission lets the tracker send email; the application does not request permission to read, search, list or delete inbox messages.

The tracker uses the configured sending address, the single allowed reporting destination and the digest content to send reports through Gmail. The digest can contain vacancy details, fit assessments, deadlines, changes and source failures. Google processes the outgoing message and stores it according to the account's Gmail settings and Google's policies.

The tracker retains send-attempt records, timestamps, acceptance status and the message identifier returned by Gmail to help prevent duplicate sends. Provider acceptance is recorded separately from confirmed delivery; it does not establish that a message reached the inbox.

Offline access allows scheduled sending when the owner is not signed in. Access and refresh tokens are encrypted before persistent storage in the tracker's Supabase state. They are used to obtain authorised access and send the configured reports.

Job Tracker 2027's use and transfer of information received from Google APIs adheres to the Google API Services User Data Policy, including its Limited Use requirements. Google user data is not sold, used for advertising or used to train general-purpose AI or machine-learning models.

Hosting and service providers

The deployed tracker uses Microsoft OneDrive for the workbook, Streamlit for the private dashboard, GitHub Actions for scheduled execution, Supabase for encrypted operational state and backups, Google for authorisation and Gmail sending, and configured discovery providers such as Tavily. Each provider processes the information needed to provide its service under its own terms and privacy policy. Requests to official vacancy websites and supported feeds are also part of checking opportunities.

Runtime credentials are stored in private service secret settings rather than the workbook or source code. Operational state includes encrypted authorisation caches, workbook backups, discovery snapshots, run history, queued digests and email outcomes. Encryption does not remove the need to protect the hosting accounts and runtime secrets.

Retention and the owner's controls

There is no fixed automatic retention period. The workbook, operational history and backups remain until the owner removes them or the relevant provider applies its own retention rules. Pausing checks or disconnecting an account does not by itself delete existing workbooks, history, backups or sent email.

The owner can pause checks, change preferences and disable sources in Excel; disconnect account authorisation; and remove stored authorisation, history, backups or hosting resources through the relevant administration tools. Copies in provider backups or logs remain subject to that provider's policies.

Google access can be revoked in Google Account connections. Microsoft access can be managed through the Microsoft account's application permissions. Revoking authorisation prevents further authorised account access but does not recall email already sent.

These public pages

These information pages contain no tracker records, account credentials, forms, analytics scripts or advertising. When hosted on GitHub Pages, GitHub logs visitors' IP addresses for security purposes, as described in its Pages documentation. Other normal hosting requests and logs are governed by GitHub's privacy policy.

Questions or deletion requests

Contact the application owner through the user support email shown on the Google authorisation screen. Changes to this policy will be published here with an updated date.
